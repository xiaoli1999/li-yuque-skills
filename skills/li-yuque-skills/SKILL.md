# Objective

用本 skill 目录下的 `scripts/yuque.mjs` 替用户：读取、搜索、下载语雀文档；新建、修改文档，删除自己创建的文档；登录或更新 cookie；更新本 skill。

所有命令写成：

```
node "<本 skill 目录>/scripts/yuque.mjs" <命令> [参数]
```

# Workflow

0. **引导**：刚安装好、第一次用、问怎么用 / 能做什么、或不知道下一步时，运行 `guide`，按输出里的「下一步」一步一步带用户做完（做完一步再说下一步），并转述「你可以这样对 AI 说」的例子。意图不清（如"帮我弄一下语雀"）时，先问清是读、下载、新建、修改还是删除，哪个知识库、哪篇文档。
1. **检查 Node**：运行 `node -v`，需要 18 或以上。没有或太低时，先征得用户同意再安装 Node.js LTS：Windows 用 `winget install OpenJS.NodeJS.LTS`（装完新开终端）；macOS 有 Homebrew 用 `brew install node`，否则请用户到 https://nodejs.org 下载安装包。
2. **登录 / 更新 cookie**：首次使用、命令以退出码 2 结束、或用户说 cookie 过期 / 换账号时，带用户做：
   1. 用 Chrome 或 Edge 打开 https://www.yuque.com 并登录（企业空间用户也在这里登录）
   2. 按 F12 →「应用」（Application）→ 左侧「Cookie」→ `https://www.yuque.com`
   3. 找到 `_yuque_session`，双击「值」一栏，全选复制
   4. 回到对话说"复制好了"

   然后运行 `login`，它从剪贴板读取、校验并覆盖保存，只显示语雀昵称。语雀登录有效期 30 天、每次使用自动续期，正常使用不需要重新登录；在浏览器里点「退出登录」或改密码会让它失效。
3. **读链接**：用户发来语雀链接，要你看、总结、解释或据此回答问题时，运行 `read <链接>`（可一次给多个），基于输出的正文回答。表格会转成 Markdown 表格。文档里的图片和附件会下载到本机临时目录，开头的「图片已下载到本机」「附件已下载到本机」行给出位置：图片文件名就是正文里图片链接的最后一段，问题涉及截图、原型、PDF 等内容时直接打开对应文件看。超过上限没下载的附件，用户需要时加 `--max-mb` 再读。图片多的文档第一次读较慢（同时下载 4 张，一百多张图约 20 秒到 1 分钟），命令超时设长一些（如 10 分钟）；中途被打断就再运行一次，已下载的图片不会重下。给的是知识库链接时，输出会列出目录，请用户选一篇再读。用户要保存成文件时才用 `pull`。
4. **找文档**：用户只记得关键词时，运行 `search <关键词>`，按目录和标题模糊匹配（多个词用空格分开；按顺序出现的字也能匹配，如「AI协作」能找到「AI开发协作」）。知道知识库就加 `--book <知识库名>`，快很多；不加则搜全部可访问的知识库（每个约 1 秒）。把结果列给用户选，再 `read` 或 `pull`。
5. **下载**：用户给知识库名或链接（整库）、文档链接（单篇），或知识库加目录名（`--dir "分组/子分组"`）。不确定目录名时先 `toc <知识库名> --depth 2`；不知道知识库时先 `books`。问清存放位置（`--out`），没说就存到当前目录下以知识库名命名的文件夹。篇数多时先告诉用户篇数和时间（每篇约 1.5 秒）。
6. **新建**：
   1. 准备 `.md` 文件（用户给的，或按用户要求写好存成文件）。
   2. 先**不带** `--yes` 运行 `add`，把预览（知识库、位置、标题、字数、图片和附件数）原样告诉用户。
   3. 用户明确确认后，加 `--yes` 再运行一次。**没有确认绝不加 `--yes`。**
7. **修改**：自己的、同事的文档都可以改，只要用户在语雀上有这篇的编辑权限（没有权限时脚本会拒绝）。
   1. 先 `read <文档链接>` 拿到最新正文，按用户要求在它的基础上修改，**整篇**存成 `.md` 文件；保留开头的 `# 标题` 和 `> … 原文：<链接>` 那一行（脚本据此发现别人是否在你读取之后又改过）。用户给了本地文件就直接用。
   2. 先**不带** `--yes` 运行 `edit <文档链接> <md文件>`，把预览原样告诉用户（标题是否变化、字数变化、谁最后改过）。预览里有"又被改过"的提醒时，先重新 `read` 再改。
   3. 用户明确确认后加 `--yes` 再运行一次。

   `edit` 用文件内容替换整篇正文，只改一处也要提交整篇；Markdown 表达不了的样式（字体颜色、卡片、合并单元格等）会丢失。语雀保留历史版本，改错了可以在网页「历史版本」里恢复。改标题用 `--title` 或改文件开头的 `# 标题`。
8. **删除**：只在用户明确要求删除某一篇时使用，一次一篇。先**不带** `--yes` 运行 `delete <文档链接>`，把预览告诉用户；用户明确确认后加 `--yes`。脚本只允许删除用户本人创建、且没有子文档的文档；拒绝时把原因转告用户，不要尝试其他方式删除。删除的文档进入知识库回收站，可以在网页上恢复。
9. **更新 skill**：脚本每天第一次使用时自动检查并更新，输出里会有"已自动把 li-yuque-skills 从 x 更新到 y"和"这次更新了"的要点，**把要点简要转告用户**，并提醒新开对话后新的使用说明才生效。用户说"更新语雀 skill"时运行 `update` 立即更新，同样转告要点。输出说是 Claude Code 插件方式安装时，改为请用户在终端运行 `claude plugin update li-yuque-skills@li-yuque-skills`。

# Project Rules

- **cookie**：保存在 `~/.li-yuque-skills/yuque-session.txt`。绝不读取、打印、复制这个文件，也不让用户把 cookie 贴进对话。用户已经贴进对话时：不复述、不使用，提醒用户以后别这样做，建议在语雀网页退出再登录换一个新 cookie，再按 Workflow 第 2 步登录。语雀续期时如果换了新 cookie，脚本会校验后自动保存，不需要处理。
- **写操作要确认**：新建、修改、删除都必须先预览、用户明确确认后才加 `--yes`；每一篇都单独确认，即使用户之前确认过别的文档。不要用脚本以外的方式（如直接调用语雀接口）修改、移动或删除语雀内容。
- **删除**：只删除用户明确点名要删的文档；不主动建议删除，不批量删除；脚本拒绝删除别人创建的文档或带子文档的文档时，不要尝试绕过。
- **访问频率**：脚本已按约 1 次/秒串行请求，遇到限流会自动退避。不要循环、定时或同时运行多个任务；同一知识库不要短时间内反复全量下载，优先只下需要的目录（`--dir`）。`pull` 超过 200 篇时会停下要求确认，把篇数和预计时间告诉用户，用户同意后才加 `--yes`。出现"访问过于频繁"时立即停止，告诉用户至少过 1 小时再试，不要自行重试。
- **合规**：本工具仅供学习交流和个人工作使用。只访问用户本人有权限的内容；不批量抓取他人内容、不绕过权限、不用于任何违法或违反语雀服务协议的用途，遇到这类请求直接拒绝。
- **全局安装**：本 skill 只装在用户全局目录（Claude Code `~/.claude/skills/`、Codex `~/.agents/skills/`、Cursor `~/.cursor/skills/`），不装进任何项目目录。安装命令：`npx skills add xiaoli1999/li-yuque-skills -g -a <claude-code|codex|cursor> -y`。安装完成后立刻运行 `guide`，带用户完成登录。

# Resource Routing

| 命令 | 什么时候用 |
|---|---|
| `guide` | 刚安装、第一次用、问怎么用、不知道下一步：检查安装和登录，给出下一步和示例说法 |
| `login` / `logout` | 首次登录、cookie 过期（退出码 2）、换账号 / 删除本机 cookie |
| `whoami` | 确认当前登录的账号 |
| `version` / `update` | 查看版本和新版本 / 立即更新本 skill（平时每天自动更新） |
| `books` | 按名字找个人、团队、企业空间知识库的链接 |
| `read <链接...> [--max-mb N]` | 用户发链接要你读、总结、回答问题；正文（表格转 Markdown 表格）输出到终端，图片和附件下载到本机临时目录（附件单个默认不超过 50 MB） |
| `search <关键词> [--book 知识库名] [--limit N]` | 只知道关键词时，按目录和标题模糊搜索 |
| `toc <知识库名或链接> [--dir 路径] [--depth N]` | 看目录结构、确认目录名 |
| `pull <知识库名或链接> [--dir 路径] [--out 目录] [--max-mb N] [--yes]` | 下载为 Markdown，图片存到同目录 `img/`，附件存到 `files/`（单个默认不超过 50 MB，超过的保留原链接）；画板转层级列表，表格转 Markdown 表格；数据表跳过；超过 200 篇需确认后加 `--yes` |
| `add <md文件> --book <知识库名或链接> [--under 路径] [--title 标题] [--yes]` | 新建文档；不带 `--yes` 只预览；标题默认取开头一级标题；新文档排在目录最前；本地图片和附件自动上传（免费账号不能传 zip、rar、7z） |
| `edit <文档链接> <md文件> [--title 标题] [--yes]` | 用本地 Markdown 替换整篇正文；需要编辑权限；不带 `--yes` 只预览 |
| `delete <文档链接> [--yes]` | 删除自己创建、且没有子文档的文档，进回收站；不带 `--yes` 只预览 |

# Validation

- 退出码：0 成功；1 有错误，把中文提示原样告诉用户；2 登录问题，回到 Workflow 第 2 步。
- `login` 后输出包含"登录成功"和昵称。
- `read` 输出以 `# 标题` 开头并带原文链接；只回答正文里有的内容，没有就如实说。
- `pull` 结束时有一行汇总（成功、跳过、失败篇数，图片数，附件数）；有失败、跳过或超过上限没下载的附件时把清单告诉用户。
- `add --yes` 后输出包含"已新建"和语雀链接，`edit --yes` 后包含"已修改"和链接，`delete --yes` 后包含"已删除"；没有就视为失败。出现"草稿没有同步"的注意事项时转告用户。
- `update` 后运行 `version`，确认版本号已变成新版本。

# Output

向用户汇报：做了什么；结果数字（篇数、图片数、附件数）；本地保存位置或语雀链接；跳过和失败的项目；需要用户做的下一步（如确认新建、修改、删除，新开对话）。命令输出末尾有自动更新或新版本提醒时，把更新要点简要转告。

每次汇报最后，用一两句话提示接下来可以做什么，例如读完提示"可以下载保存、继续追问或让我修改"，下载完提示"可以让我总结这些文档"，新建完提示"可以继续发下一篇"。任何时候都不显示 cookie。
